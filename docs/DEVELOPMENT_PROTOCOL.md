# Shared engineering completion protocol

The active development source is authoritative; a configured sanitized Git
publication repository and isolated candidate are distinct derived artifacts.
Never treat an old checkout or executable as the current source without hashes.

For each coherent maintenance unit, Codex and Antigravity must:

1. Read the current private continuation, verify identities and reconcile newer
   human work. Preserve production data and the installed application.
2. Finish the bounded implementation and independently inspect the result.
3. Run focused tests, preserving actual evidence and distinguishing deterministic
   checks from genuine model acceptance. Do not run prohibited native workloads.
4. Review source privacy, dependencies and licensing. Classify unknown files in
   the existing exact-path sync policy; preserve sanitized repository-owned files.
5. Use the configured publication repository's `scripts/auto_sync.py prepare`.
   Review its immutable snapshot, exact preview and real test receipt.
6. Accept that exact completed batch using its returned ID/digest and review
   acknowledgements. The bounded runner handles transactional source sync,
   actual-index validation, development-branch commit/push and exact remote CI.
7. Update private engineering state, change evidence, rollback identity and next
   action. Never equate source-publication COMPLETE with product release readiness.

Follow `docs/AUTO_SYNC.md` in the configured publication repository for commands
and recovery. Agent instructions are the supported integration mechanism; no
unavailable agent hook is assumed. File debounce does not prove task completion.

Candidate building and milestone documentation are separate acceptance gates.
Do not promote main, upload unlicensed binaries, replace models or install a
production application through this source-publication protocol. Native origins,
redistribution rights and clean-Windows verification must remain explicit where
unresolved. Private paths, prompts, logs, databases and snapshots never belong in
the publication repository.
