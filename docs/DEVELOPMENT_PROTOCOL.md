# Shared engineering completion protocol

The active development source is authoritative; a configured sanitized Git
publication repository and isolated candidate are distinct derived artifacts.
Never treat an old checkout or executable as the current source without hashes.

For each coherent maintenance unit, Codex and Antigravity must:

1. Read the current private continuation, verify identities and reconcile newer
   human work. Preserve production data and the installed application.
2. Finish the bounded implementation and independently inspect the result.
3. Run focused tests, preserving actual evidence and distinguishing deterministic
   checks from genuine model acceptance. Do not run prohibited native workloads.
4. Review source privacy, dependencies and licensing. Classify unknown files in
   the existing exact-path sync policy; preserve sanitized repository-owned files.
5. Use the configured publication repository's `scripts/auto_sync.py prepare`.
   Review its immutable snapshot, exact preview and real test receipt.
6. Accept that exact completed batch using its returned ID/digest and review
   acknowledgements. The bounded runner handles transactional source sync,
   actual-index validation, development-branch commit/push and exact remote CI.
7. Update private engineering state, change evidence, rollback identity and next
   action. Never equate source-publication COMPLETE with product release readiness.

Follow `docs/AUTO_SYNC.md` in the configured publication repository for commands
and recovery. Agent instructions are the supported integration mechanism; no
unavailable agent hook is assumed. File debounce does not prove task completion.

Unattended publication executes a private, accepted commit snapshot through the
hash-verifying frozen supervisor. Never point its scheduled action at an editable
working-tree controller. Develop controller changes separately, review their
exact source and remote CI, then activate a new accepted runtime explicitly.
The controller's commit and each published application's source commit are
separate identities; neither is permission to install a production update.

## On-demand completion events (current operating mode)

The owner has disabled the legacy periodic source-sync and candidate-build
tasks. Keep them disabled. Do not restore five-minute polling, create a service,
register another scheduler or automatically change task principals/actions.

After a coherent unit passes tests and privacy/dependency/source review, use
the existing prepare/accept protocol. Then explicitly invoke the configured
private completion hook with that exact accepted batch ID. Codex and Antigravity
must perform this handoff as part of finishing an accepted unit; file changes
or elapsed time alone are never an event or an approval. The hook location and
reviewed profile are recorded in the local canonical source contract, outside
the publication repository. If they are absent or fail integrity checks, stop
and report the boundary rather than silently enabling a timer.

The hook delegates to the existing frozen source controller, existing locks,
journaled transaction, actual-index checks, non-force private push and exact
remote CI. It does not accept batches, implement Git writes, retry terminal
failures or create a competing queue. CI observation is bounded to the active
completion event; it must end when complete, failed, offline or timed out.
There is no idle polling between completed changes. Network deferral requires
an explicit new resume event, preserving the existing retry evidence.

After exact successful CI, an explicitly requested candidate handoff invokes
the existing frozen isolated worker once. Its provenance, execution-profile,
resource, payload and packaged-smoke checks remain authoritative. Documentation
only changes do not justify an application rebuild. A dispatcher receipt or
an IDLE worker does not mean a new EXE was built or accepted. Failed CI never
authorizes candidate promotion. Never relabel a failed source batch or force
candidate pointers to unblock this handoff.

The local hook runs under the current limited user and existing Git credentials,
has no listener or persistent service, and uses a hidden console inherited by
ordinary child console processes. This launch presentation does not fix the
separate Windows process-cleanup defect. Repository-owned controller repairs
retain their narrow reconciliation and subsequent CI/frozen-upgrade gates.

Use GitHub-hosted Windows build jobs only after portable, complete approved
dependency/provenance inputs and licensing allow them. A machine-specific
private environment receipt is not a cloud build recipe. Keep candidate
artifacts private. Public Releases, visibility changes and production installs
always require separate explicit approval of destination, version and hashes.

Candidate building and milestone documentation are separate acceptance gates.
Do not promote main, upload unlicensed binaries, replace models or install a
production application through this source-publication protocol. Native origins,
redistribution rights and clean-Windows verification must remain explicit where
unresolved. Private paths, prompts, logs, databases and snapshots never belong in
the publication repository.
