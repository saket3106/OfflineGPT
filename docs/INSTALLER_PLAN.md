# Recommended future Windows installer architecture

This is a proposal, not an implemented migration or current release acceptance.

1. **Small application package:** signed Windows x64 per-user installer or MSIX, containing the Qt/Python shell, compiled frontend and license notices. Keep debug symbols, test fixtures and build caches out of the production payload. Choose MSIX versus a conventional installer only after validating writable paths, subprocess workers and required runtime access.
2. **Separate native engine packs:** immutable versioned chat/vision, FLUX and Whisper runtime directories with their own matching DLL sets. Validate exact native provenance, architecture, CUDA/driver requirements, flags/protocol and SHA-256 manifests. Do not mix identically named DLLs from unrelated packs. Preserve Qt's ICU isolation.
3. **External model store:** provision or select licensed models separately, with explicit consent and integrity verification. Store one validated weight copy per model and reference it from compatible engines. No automatic replacement, quantization or silent gated-model downloads. Keep model files outside application update/rollback bundles.
4. **Independent user-data directory:** migrate chats, settings, Library metadata, documents, generated files and journals into a per-user data location, only through a separately reviewed migration with backups. Current code still has `APP_DIR` ancillary paths, so this separation requires application work before installation under a read-only directory.
5. **Safe upgrades:** stage a new immutable application/engine version, validate signatures/hashes, back up the SQLite database consistently with WAL state, apply versioned transactional migrations, run bounded acceptance, then switch versions atomically. Keep a small previous app/engine rollback; do not duplicate tens of gigabytes of unchanged weights for every code update.
6. **User control:** uninstall removes application binaries while preserving data/models by default. Destructive cleanup must be separate, explicit and verified. Library original/version relationships and uncertain deletion journals survive upgrades.
7. **Release evidence:** clean-checkout build, dependency and native SBOM, complete notices/source obligations, reproducible artifact manifest, unsigned/signed hashes, supported-hardware matrix and genuine model/UI/data-integrity acceptance. Mock unit tests alone cannot authorize production installation.

Use GitHub for reviewed source history. Distribute signed installer/engine artifacts through a separate release mechanism after licensing and acceptance, and use upstream-authorized model acquisition. Git LFS is unnecessary for this source-only export and should not become a store for private databases or model backups.
